# Court Decree Residual Duty Ledger

## STAGE 1

- **Objective/users:** Record which numbered obligations in one public court consent decree were terminated by a later court order and which expressly survive. Oversight dashboards and policy-maintenance systems can query a paragraph-scoped residual-duty vector. This is not a compliance, constitutional-policing, liability, or legal-advice judgment.
- **Trust problem/GenLayer need:** A headline saying a decree was “partially terminated” can be misread as ending all oversight, while an order may terminate enumerated paragraphs and retain other subject areas. The consequential question requires reconciling an original decree with a later judicial order's natural-language set operations. Independent validators should agree on the same terminated/surviving paragraph ranges before a downstream status changes. If a court publishes a trusted normalized machine-readable residual set, deterministic software is preferable.
- **Core mechanism:** Seal `(court, case number, decree document identity, later order identity, target paragraph ID)` and classify `decree_identity_match`, `order_final`, `target_terminated`, `target_survives`, `scope_ambiguous`. The contract stores a paragraph-specific event, not a broad “decree complete” boolean. Terminated and surviving cannot both be true.
- **Actors:** registry owner, public assessor, downstream reader. One contract, no party submissions, personal records, penalties, payments, or external calls.
- **Concrete public source set, checked 2026-09-21:** the DOJ Civil Rights Division's [Special Litigation case summary](https://www.justice.gov/crt/special-litigation-section-case-summaries) states that the Newark court granted partial termination on May 17, 2024. The DOJ [case-document page](https://www.justice.gov/crt/case-document/united-states-v-city-newark-consent-decree) dates the decree May 5, 2016. Its older [file/868131 PDF](https://www.justice.gov/crt/file/868131/dl) starts with supplemental motion Document 4 and proposed attachment Document 4-1, so it is **not** the source used to prove the entered decree. The separate DOJ-hosted [entered decree PDF](https://www.justice.gov/media/831031/dl?inline=) has `Case 2:16-cv-01731-MCA-MAH Document 5 Filed 05/05/16` page headers throughout, including PDF page 22 (one-based) / ECF page 21 containing Paragraph 44's first-line-supervisor review duty and ECF page 75 containing Paragraph 225. The DOJ-hosted [partial-termination order](https://www.justice.gov/crt/media/1379811/dl) is **Document 360**, filed `05/17/24`, identifies the same case and Consent Decree ECF 5, and its operative text says the joint motion is granted and expressly terminates Paragraphs 5–12, 14–19, 21–28, 43, 55–62, 103–104 and 105–110; provisions not described in its termination subsection remain intact and monitored. The PDF title has a `[PROPOSED]` OCR artifact, so finality is bound to the filed date and operative `ORDERED`/`GRANTS` text plus the DOJ case summary, not the title alone. Both consequential court instruments are PDF-only; web-indexed text does not prove current GenVM can extract them.
- **Field mapping/counterexamples:** entered decree ECF 5 page header and Paragraph 44 text on PDF page 22 (one-based), ECF page 21, bind the registered target to the entered instrument, not merely Document 4-1; Paragraph 225 on ECF page 75 bounds the universe. Order caption/case/ECF bind modification identity; filed order and “GRANTS” bind finality; explicit ranges bind the terminated set; intact-and-monitored text binds residual semantics. Paragraph 43 is terminated. Paragraph 44 exists in entered ECF 5, is outside every terminated range, and therefore is `SURVIVES_THIS_ORDER` for this exact order only. A joint motion without a granted order is `NOT_FINAL`.
- **Validator/evidence model:** validators independently retrieve the sealed decree/order sources and classify one target paragraph against a bounded canonical range list. Exact equality is required for identities, finality, target result and evidence state. Contract logic performs the final set-membership check from the consensus-bound ranges; explanations and subject labels are nonconsequential.
- **Consequential state/reuse:** append-only `TERMINATED | SURVIVES | NOT_FINAL | UNRESOLVED` at exact decree/order/paragraph revision. Integrations may hide a retired checklist item or retain an active one only with all qualifiers. Reusable primitive: judicially authorized **set subtraction with explicit residual obligations**.
- **Closest baseline/material differentiation:** `Court Order Milestone Compliance Registry` links ordered deadlines to filed reports; it does not alter which underlying paragraphs remain legally operative. `Superfund Partial Deletion Boundary Covenant` distinguishes included/excluded media or parcels in an administrative NPL rule; this candidate subtracts enumerated paragraph obligations from a judicial instrument and preserves the complement. `Incident Remediation Closure Covenant` assesses real-world implementation evidence, not a court's formal modification. The trust problem, state transition and output key are materially distinct. Difference high; the Paragraph 43/44 counterexample cannot be represented by milestone completion or geographic/media deletion.
- **Risks/assumptions/feasibility:** legal-document identity, later orders, overlapping ranges and PDF access. MVP is one case, one decree, one granted order, one paragraph query and no interpretation of substantive compliance. Later build must test DOJ PDF retrieval/extraction in current GenVM or locate authoritative HTML/converted bytes with exact parity; until then Studio Dev feasibility is conditional. One nondeterministic classification plus deterministic set membership is otherwise small.
- **Stage 1 acceptance:** public exact case/order, positive and adjacent negative paragraph, motion-vs-order finality, no whole-decree claim, materially distinct mechanism/name, fail-closed PDF/runtime risk.

## STAGE 2

- **Domain model/vocabulary:** `Decree` stores court/case/ECF, source digest and bounded paragraph universe `1..225`; `ModificationOrder` stores document/filed identity, predecessor decree, canonical terminated ranges, source digest and revision; `DutyReview` stores target paragraph and result. `SURVIVES_THIS_ORDER` is the complement within that bound decree/order pair, not a claim against unregistered later orders.
- **Lifecycle:** decree `DRAFT -> SEALED -> ACTIVE -> SUPERSEDED`; order `REGISTERED -> SEALED -> ASSESSED_FINAL | NOT_FINAL | UNRESOLVED`; review `OPEN -> TERMINATED | SURVIVES | UNRESOLVED`. A later order creates a successor revision and never rewrites history.
- **Invariants/storage:** exact case and decree identity; 1–2 allowlisted HTTPS sources; unique ordered non-overlapping paragraph ranges; bounded positive integer IDs; target inside registered decree universe; `TERMINATED xor SURVIVES` only after finality and identity match; motion or conflicting order cannot yield favorable state. Store hashes, small integers/ranges, enums, revision links and timestamp/day—not full documents.
- **Public API:** `register_decree`, `seal_decree`, `register_order`, `seal_order`, `assess_order`, `review_paragraph`, `supersede_order`, `get_order`, `get_review`, `read_residual_duty`. The read method returns case/order/paragraph qualifiers with status.
- **Authorization/input validation:** owner manages decree/order lifecycle; public assessment/review/read. Validate HTTPS/allowlist, exact case format, ECF/document IDs, paragraph bounds, sorted disjoint ranges, URL uniqueness, content size/hash, lifecycle and stale revision. Reject caller-supplied model result and ambiguous range syntax.
- **Evidence/prompt/untrusted boundary:** order and decree bytes are delimited untrusted evidence. Prompt ignores embedded instructions and requests a strict schema containing only identity/finality and normalized range fields. No link-following, broad search or inference from press headline. Exact document hash drift makes the sealed revision unresolved.
- **Leader/validator/Equivalence Principle:** leader and validators independently fetch and extract `(case_match, decree_match, order_identity, granted, terminated_ranges, residual_clause_present, evidence_state)`; exact-match every consequential field. Contract validates/sorts ranges and deterministically decides target membership. Explanation and subject-area prose never set state.
- **Decision versus explanation:** identities, finality, ranges, residual-clause flag, evidence state and derived paragraph result are consequential. Citation snippets/reasons are bounded display fields only.
- **Errors/retry/duplicate/replay/appeal/timeout:** unavailable PDF, parser ambiguity, overlapping/malformed ranges, identity mismatch or disagreement leaves no favorable write/`UNRESOLVED`; identical sealed replay is idempotent; changed bytes or later order require successor; appeal supplies a new controlling court order; timeout preserves prior revision.
- **Downstream consequences:** a checklist may retire only the exact terminated paragraph under the exact final order revision; surviving and unresolved items remain active/manual. No payout, penalty, reputation score, policing-quality judgment, or full decree termination flag.
- **Direct/integration/E2E matrix:** Newark Paragraph 43 terminated; original-decree Paragraph 44 exists and survives this order; boundaries 12/13, 19/20, 28/29, 62/63, 110/111; outside universe 0/226; wrong case/ECF; joint motion only; proposed/unsigned order; missing residual clause; overlapping ranges; changed decree/order PDF hash; hostile document text; malformed JSON; validator range-bit disagreement; auth/replay/supersession/timeout; Studio Dev finalized transaction and authoritative readback.
- **CLI deployment plan/minimum architecture:** later main build uses canonical GenLayer CLI with explicit wallet on Studio Dev, lint/direct tests before one bounded live E2E and readback. Research performs none. Expected minimum: one contract, one test module, README, source manifest and evidence matrix; no docket crawler, legal ontology, monitor, UI, notifications, cross-contract calls or funds.
- **Acceptance/status:** complete identity/finality/range binding and negative boundaries specified. `CANDIDATE — NOT YET ANONYMOUSLY APPROVED`; exact DOJ PDF access/extraction remains a mandatory build-stage feasibility gate.

## BUILD-STAGE RUNTIME CORRECTION (2026-09-27)

Studio Dev GenVM v0.6.0-rc5 was probed directly against the two PDF URLs above. `gl.nondet.web.render(..., mode="text")` returned an empty string for both PDF sources; `gl.nondet.web.get(...).body` returned PDF bytes that are not UTF-8 text. The contract does not claim PDF extraction that the runtime cannot perform.

The runtime-feasible registered source pair is now the DOJ HTML consent-decree page and the DOJ Special Litigation case-summary page. Both render as stable text in Studio Dev. The first binds the dated consent-decree identity; the second binds the same case and the Court-granted May 17, 2024 partial termination. The registered canonical terminated-range string remains sealed input and is checked by contract-side range equality; source text cannot invent or reorder it. The PDF URLs remain research evidence for the exact instruments, while the HTML pages are the registered source revisions for the build E2E.
